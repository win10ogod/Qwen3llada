# Changelog / Version history

## Stable: v4 no-tool-parser

File: `templates/stable/chat_template.jinja`

Current recommended template.

### Kept

- Permanent thinking mode.
- Preserved historical reasoning.
- `enable_interleaved_thinking`, default `true`.
- `medium` default reasoning effort.
- Inline reasoning-effort control tags are scanned before rendering and removed from prompt text.
- Developer/system head-message support from the evolved template.

### Tool serialization rule

- Mapping arguments are serialized as Qwen XML parameters.
- String arguments are preserved verbatim.
- No JSON parser, schema repair, normalization, or semantic inference is performed by Jinja.

### Known limitation

This template does **not** eliminate all premature `stop` events seen under DSH + vLLM/EVE/Qwen-style serving. The remaining issue is tracked separately because current evidence does not isolate the chat template as the root cause.

## Broken archive: v4 minimal mapping-only

File: `templates/archive/broken/v4-minimal-mapping-only.jinja`

Intent: remove the large K3-derived JSON parser and return closer to the original template.

Why retired:

- Tool arguments are iterated with `|items`.
- This assumes arguments are mappings.
- OpenAI-compatible providers frequently preserve `function.arguments` as a JSON string in message history.
- A raw string therefore has no safe mapping iteration path in this version.
- The tool prompt also retains the original strict `ONLY reply ... NO suffix` wording, which remained a suspect in tool-use premature-stop investigations.

## Broken archive: v3 tool-parser

File: `templates/archive/broken/v3-tool-parser.jinja`

Changes introduced:

- `enable_interleaved_thinking` support.
- reasoning-effort control-tag pre-scan.
- looser anti-stall tool instructions.
- a full Jinja JSON parser adapted from the K3 template for string tool arguments.

Why retired:

- The JSON parser made the template responsible for interpreting and reconstructing tool arguments.
- That crossed the serializer/semantic boundary and made tool failures harder to attribute.
- Tool-call regressions were observed in the same development period, including schema-validation errors and a `noop` failure in DSH.
- The observed `activeForm`/missing-`status` Todo error was **not proven** to be generated by the parser itself. The important conclusion is narrower: the parser added risk without being necessary, so it was removed.

---

## Broken archive: v2 K3-derived parser / strict tool flow

File: `templates/archive/broken/v2-k3-json-parser.jinja`

Changes introduced:

- Permanent thinking behavior.
- early interleaved-thinking support.
- K3-derived parser helpers such as `jp_*` and `numstr`.
- stricter tool-call transition language.

Why retired:

- The template became much larger and harder to audit.
- The strict tool-flow instruction could create a conflict when the model wanted to emit conversational text and then call a tool.
- The K3 parser solved a problem that belongs to provider/framework serialization, not to a Qwen Jinja template.

## Baseline: original 2026-09-27

File: `templates/archive/baseline/original-2026-09-27.jinja`

The original 171-line template used as the baseline for this investigation.

Notable behavior:

- `enable_thinking` exists and can disable thinking.
- `preserve_thinking` exists.
- default reasoning effort is `xhigh`.
- strict tool-call prompt uses `ONLY reply ... with NO suffix`.
- tool arguments are expected to behave like mappings and are expanded with `|items`.

This file is preserved as a reference baseline, not labeled "broken" wholesale. Some of its assumptions are simply incompatible with the target DSH / OpenAI-compatible history shapes used in this investigation.
